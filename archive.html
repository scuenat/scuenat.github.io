A Grammar for Tools

MCP gave AI agents a dictionary. What it still lacks is a way to say how tools combine
essay
ai
agents
architecture
mcp
MCP lets every tool define itself, like words in a dictionary. Nothing in the protocol says how tools combine, so every agent rebuilds that knowledge on every run and forgets it at the end. I argue that the missing piece is a small grammar: rules over kinds of tools, and habits of specific tools, computed from schemas, declared by authors, observed in use and imposed by policy. OpenAPI, Arazzo and the semantic web tried parts of this before; what is new is a reader that can use it. I borrow the design principles from neural networks, without training one.

Position paper

Stop Reviewing Pull Requests

A provocative position paper: approve what you cannot undo, watch everything else
paper
position
ai
agents
programming
A deliberately provocative position paper. Per-change human code review was the right control when code was written by hand and late fixes were expensive. With agentic coding, a simple cost model and a simulation suggest a different rule: a person approves only what cannot be undone, through a thin gate at the point of no return, and everything else merges under rules and is watched by a daily audit of the whole codebase. The paper states the conditions under which the rule holds, the predictions that would prove it wrong, and a protocol to test them.
